## 1. Architectural Role & Boundary

OWASP ZAP is an industry-standard web application security scanner. In SHARAY:
- **Operation**: `zap.passive`
- **Profile**: `passive_web` (Risk: `passive`)
- **Strict Limitation**: Passive scanning only! Active attack plugins (SQL injection, XSS payloads, command injection) are disabled. ZAP inspects HTTP requests and responses generated by safe spidering or browser proxies without mutating or injecting attack payloads.

## 2. Headless Automation Framework (AF) Invocation

ZAP is invoked in non-daemon command-line mode via its Automation Framework (`-cmd -autorun`):
```sh
zap.sh -cmd -autorun /path/to/plan.yaml
```
The automation plan is generated dynamically by the adapter into a scratch directory:
```yaml
env:
  contexts:
    - name: "sharay_context"
      urls:
        - "https://target.laboratory.local:8443"
      includePaths:
        - "https://target.laboratory.local:8443/.*"
      excludePaths: []
jobs:
  - type: passiveScan-config
    parameters:
      maxAlertsPerRule: 10
      scanOnlyInScope: true
  - type: spider
    parameters:
      context: "sharay_context"
      maxDuration: 1
      maxDepth: 3
  - type: passiveScan-wait
    parameters:
      maxDuration: 1
  - type: report
    parameters:
      template: "traditional-json"
      reportDir: "/path/to/scratch"
      reportFile: "zap-report.json"
```

## 3. Hardened Report Parsing

ZAP exports a `traditional-json` report containing site-level alerts:
- Alerts are grouped by plugin ID, risk code, and confidence.
- The parser extracts:
  - `alert_id`: pluginId.
  - `name`: sanitized alert title.
  - `risk`: mapped to SHARAY severity (`info`, `low`, `medium`, `high`).
  - `confidence`: mapped to SHARAY confidence scale.
  - `uri`: URL where issue was identified, strictly stripped of query parameters and credentials.
  - `solution`: remediation guidance.
- Proof/evidence is redacted with `packages/secret_patterns.py` to prevent credential exposure.
