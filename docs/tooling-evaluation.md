# Aegis tooling evaluation

Research date: October 11, 2026. This is a selection and integration plan, not an installation report. The initial Aegis audit found no application code or established product stack; the first implementation uses a Python standard-library engineering runner and a local browser dashboard. Application frameworks, database, hosting, authentication and AI runtime remain undecided. Tool choices below are engineering recommendations conditional on those decisions.

[ESLint](https://eslint.org/docs/latest/use/getting-started), [Prettier comparison](https://prettier.io/docs/comparison) | Project-local development dependencies and lockfile. ## Dashboard evidence contract

The initial dashboard should display recorded engineering results and label missing integrations as unavailable. CPU, memory, API latency, database performance and network activity require actual workloads plus appropriately scoped instrumentation; a project inventory cannot establish them. This follows the need for emitted signals described by [OpenTelemetry](https://opentelemetry.io/docs/what-is-opentelemetry/).

Codex has documented telemetry surfaces, but their scope matters. Non-interactive `codex exec --json` emits execution events and completion usage for that run; the examples include command execution and token counts. A separately invoked CLI workflow can capture those records. [Non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode) Codex configuration also exposes OTel log, trace and metrics exporters, including an explicit opt-in for raw user-prompt logging. [Configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference)

Neither documentation nor this local inventory establishes an active, comprehensive feed of this desktop chat's internal tool calls, commands, file writes, reasoning tokens or billing. Do not scrape private session/credential stores to approximate one. Show unavailable fields as unavailable, preserve provenance, and import only supported exports. Cost estimates require observed token categories, the actual model, applicable rate source/date and billing mode; subscription limits are not per-task dollar costs.

Recommended rollout: validate the dependency-free seed; add reviewed Gitleaks scanning; select one SCA path when artifacts exist; add one SAST path and stack-native checks when application code exists; add browser/load/profiling and runtime telemetry against measured needs. Remote CI execution, scanner coverage, production security and performance improvements must each have their own evidence before being reported as achieved.
