1. Executive Summary & Ground Truth Status

This document formalises the capability gap between the current operational baseline of SHARAY and the state-of-the-art target defined in OSP-ARCH-001. It establishes a unified, empirical audit of what has genuinely been executed and verified in code versus what remains in drafts or requires net-new development.

Recent Verified Milestone (Assessment c13911c7-2d15):
A comprehensive live assessment was executed against a live test target (pentest-ground.com:4280). The pipeline completed all 14 stages in 331.58 seconds with zero worker crashes. It discovered 19 confirmed vulnerabilities across Port Scanning (Port 6379 Redis exposed), Active Command Injection (cmd on /phpinfo.php), SSRF (url parameter), Information Disclosure, and Missing Security Headers. Every finding generated an executable, reproducible curl Proof-of-Concept block, and the resulting PDF report rendered the mandatory diagonal tiled watermark "sharay by shardul" with zero compression defects.

While the detection and multi-stage crawling pipelines are robust, true State-of-the-Art (SOTA) capability requires transitioning from speculative detection to deterministic verification, multi-step exploit chaining, and headless browser dynamic validation.

2. Defect Triage & Current Code State

2.1 Defect 1: Target Resolution Failure (packages/security_policies/__init__.py:315)

Observed: Target host did not resolve. immediately terminated scans when any hostname in a target set was invalid or transiently unresolvable.

Root Cause: resolve_pinned() caught generic OSError from socket.getaddrinfo() and raised an unbranchable prose PolicyError("Target host did not resolve."). Furthermore, input URLs with explicit schemes, trailing slashes, or custom ports reached the raw resolver un-normalised.

Remediation Status: Target normalization helper and typed error codes (NXDOMAIN, SERVFAIL, NO_RESOLVER) drafted in drafts/gemini/sota_scanner_enhancements.py. A per-target isolation guard is required so unresolvable targets emit a typed record without aborting peer scans.

2.2 Defect 2: Report Export Resource Exhaustion (aegis/api.py:1084)

Observed: HTTP 500 / Worker timeout when downloading large PDF reports with embedded screenshots and extensive vulnerability tables.

Root Cause: GET /api/v1/reports/{id} invoked ReportLab's render_report() synchronously inside the FastAPI request thread. In-memory base64 buffers and unpaginated tables exceeded memory thresholds under concurrent loads.

Remediation Status: PDF compression bug solved (pageCompression=0). The asynchronous rendering pipeline (POST /reports -> 202 Accepted -> isolated worker subprocess -> signed URL download) is scheduled as Sprint 1 P0.

3. Principal Architect Pushback & Technical Refinements

As invited by the Programme Owner, the Senior Technical Lead provides four critical architectural pushbacks on OSP-ARCH-001 to avert known traps and guarantee delivery.

Pushback 1 on Requirement G2: Do NOT Train a Transformer from Scratch.
OSP-ARCH-001 §5.G2 proposes training a custom tokeniser and small transformer from scratch for attack-chain synthesis. This is a classic machine learning engineering trap. Training a foundation transformer from scratch requires billions of tokens, massive GPU compute, and extensive RLHF just to achieve basic grammatical and syntactic competence, almost certainly producing a fragile model with poor world knowledge.

Approved Architectural Refinement: Employ Distillation / Parameter-Efficient Fine-Tuning (LoRA / QLoRA) on top of state-of-the-art open code models (e.g. Qwen 2.5 Coder 7B or Llama 3.3 8B), constrained by AutoPyVerifier executable validation grammars. Candidate attack steps are generated via temperature-sampled reasoning and scored deterministically by Python verifier scripts. If local agreement is low, escalate to frontier APIs (Gemini 1.5 Pro / Claude 3.5 Sonnet). This delivers superior reasoning at 1% of the compute cost and zero pre-training risk.
Pushback 2 on Requirement E3/E4: Deterministic WAF AST Mutation Before Bandit Learning.
OSP-ARCH-001 §5.E3 relies on a reinforcement learning multi-armed bandit to discover WAF evasions in real-time. In production environments, live bandits burn hundreds of probe requests exploring ineffective mutations, rapidly triggering target rate-limits or Cloudflare/AWS WAF IP bans.

Approved Architectural Refinement: Implement Deterministic Abstract Syntax Tree (AST) Mutation Matrices first. The engine detects the specific WAF fingerprint (e.g. Cloudflare, AWS WAF, ModSecurity) and applies proven, syntax-preserving transformations (e.g. inline comment splicing /*!50000SELECT*/, Unicode normalization, hex encoding, alternative SQL operators) in bounded, deterministic batches. The bandit should only be used to select among pre-validated transform profiles, capping exploratory noise.
Pushback 3 on Category H: Post-Exploitation Must Be Hard-Gated Behind Operator Arms.
OSP-ARCH-001 Category H specifies automated payload staging, reverse shell handling, and loot harvesting. While essential for offensive depth, autonomous lateral movement without explicit, cryptographically verifiable operator authorization violates legal and safety boundaries and risks production data corruption.

Approved Architectural Refinement: All Category H operations are strictly quarantined behind a three-factor safety gate: (1) System state must be HUMAN_OWNED, (2) The target scope record must carry an immutable ALLOW_ACTIVE_EXPLOIT signature, and (3) The operator must explicitly confirm the pre-notification countdown (Requirement D4). Autonomous agents may propose post-exploitation plans, but cannot execute them without human confirmation.
Pushback 4 on Sprint Sequence: Ground-Truth Evaluation Lab (K1) Must Coincide with Sprint 1.
OSP-ARCH-001 §8 defers full evaluation framework completion. However, enforcing the Finding State Machine (C1) and 3x cold reproducer (C2) requires a deterministic, always-available target lab.

Approved Architectural Refinement: Containerized local target fixtures (DVWA, OWASP Juice Shop, and a custom vulnerable REST API) must be stood up immediately in Sprint 1 to provide ground truth for cold replay validation.
