# Specification traceability and acceptance checklist

The original [product specification](PRODUCT_SPECIFICATION.txt) is retained verbatim. It contains 1,067 logical lines, including its unterminated final line; `wc -l` counts 1,066 newline characters. Every logical line is indexed below exactly once. A grouped entry keeps all instructions in its linked range in scope; it does not replace their individual wording or weaken their requirements.

This checklist is a backlog and verification record. **Designed; verification pending** means this increment has a concrete implementation plan but has not yet met the complete linked requirement. **Planned / unavailable** means the capability cannot be used in the current local increment. **Partial** requires evidence and an explicit remaining limit. **Passed** requires an actual recorded test or inspection, not the existence of code. The 24 criteria below now record the tested first-slice boundaries and remaining product-wide work. The product must not be called complete while AI, isolation or other required capabilities remain unavailable.

The [implementation plan](IMPLEMENTATION_PLAN.md) documents the local desktop adaptation: Python launcher, Next.js static UI, loopback FastAPI, SQLite/Alembic and a dedicated Python worker. PostgreSQL, Redis, object storage and isolated scanner containers remain server-phase requirements. The executable scanner scope is an explicitly approved literal loopback laboratory. Production deployment and arbitrary network testing are unavailable.
